Why ArrayLab?

Arrays are the most fundamental building block in computer science, representing contiguous blocks of memory. While theoretical textbooks describe element shifts and logarithmic divisions abstractly, visual manipulation makes algorithmic mechanics intuitive.

ArrayLab bridges theory and practice by rendering memory byte spans, animating each physical shift, enforcing preconditions (like sorted input in Binary Search), and keeping track of empirical comparison counts.

Educational Concept

Because arrays are allocated in unbroken, contiguous memory slots, the operating system does not need to traverse through previous items to find an element at index i. Instead, it computes the memory offset directly via standard pointer arithmetic: multiplying the index by the byte width of the data type. This is why array indexing executes in strictly constant O(1) time.

How Array Insertion Works

1. Boundary Check: Verify that the requested index i satisfies 0 ≤ i ≤ n and that the array has sufficient capacity.
2. Rightward Shift: Beginning from the last element at index n - 1 down to index i, copy each element one position to the right (A[k + 1] = A[k]) so that no data is prematurely overwritten.
3. Element Placement: Once the slot at index i is vacated, store the new value.
4. Complexity: Worst-case O(n) when inserting at index 0 (shifting all n elements). Best-case O(1) when appending to the end (0 shifts required).

How Array Deletion Works

When an element is deleted from the middle of an array, the elements after it are shifted one position to the left (A[k] = A[k + 1]) until the entire gap is sealed. Finally, the trailing redundant slot is truncated, shrinking the logical length of the array from n to n - 1.

Worst-case complexity: O(n) when deleting index 0 (shifting all n - 1 remaining elements). Best-case O(1) when deleting the last element at index n - 1 (0 shifts).

Linear Search Complexity Analysis

  • Best Case: O(1) — The target happens to be at the very first position (A[0]), requiring exactly 1 comparison.
  • Average Case: O(n) — On average, the target is located around the middle of the array, requiring approximately (n + 1) / 2 comparisons.
  • Worst Case: O(n) — The target is at the final position (A[n - 1]) or does not exist in the array, requiring n comparisons.
  • Space Complexity: O(1) — Only a pointer/index variable is maintained.

Binary Search Principle

Binary search is an optimal divide-and-conquer algorithm that operates strictly on sorted arrays. By comparing the target with the middle element A[mid], half of the remaining elements can be immediately eliminated:

  • If A[mid] == target, the search terminates with success.
  • If A[mid] < target, all elements in [low .. mid] are guaranteed smaller than the target, so we advance low = mid + 1.
  • If A[mid] > target, all elements in [mid .. high] are guaranteed larger than the target, so we advance high = mid - 1.
  • Complexity: O(log2 n) worst case. For 1,000,000 elements, at most ~20 comparisons are ever needed!
